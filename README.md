## ما هذه المنصة؟

نظام إدارة محتوى مصغَّر (Mini-CMS) مصمَّم خصيصاً لمركز تدريب شركة ترسانة الإسكندرية.
**لا شيء من محتوى الموقع مكتوب داخل الكود** — الشعار واسم المركز والعنوان والهواتف ورقم واتساب
والتخصصات والمواد والكتب والفيديوهات والأخبار والإعلانات والصور، كلها تُدار من لوحة الإدارة
وتُحفظ في قاعدة البيانات وتظهر على الموقع فوراً.

## البنية التقنية (Technology Stack)

| الطبقة | التقنية | لماذا |
|---|---|---|
| الواجهة | **React 18 + TypeScript + Vite** | سرعة بناء، تقسيم حزم تلقائي، Type Safety |
| التنسيق | **Tailwind CSS 3** (RTL) | نظام تصميم موحّد بلا CSS مكرر |
| التوجيه | **React Router 6** | تحميل كل صفحة عند زيارتها فقط |
| إدارة البيانات | **TanStack Query 5** | تخزين مؤقت ذكي وتقليل الطلبات |
| قاعدة البيانات | **Supabase (PostgreSQL)** — الخطة المجانية | Postgres كامل + RLS + Auth + Storage |
| المصادقة | **Supabase Auth** | للإدارة فقط |
| الملفات | **Supabase Storage** | صور وكتب PDF ومرفقات |
| عرض PDF | **PDF.js** (مفتوح المصدر) | لا خدمة مدفوعة |
| Excel | **SheetJS** (مفتوح المصدر) | يعمل داخل المتصفح، لا يُرفع الملف لأي خدمة |
| الفيديو | **YouTube Embed** | لا تخزين ولا تكلفة نطاق ترددي |
| واتساب | **wa.me Click-to-Chat** | مجاني، بلا واجهة برمجية مدفوعة |
| الأيقونات | **Lucide** | مفتوح المصدر |
| الاستضافة | **Cloudflare Pages** (أو Vercel / Netlify) | مجانية مع CDN عالمي |

> **قابلية تبديل المزوّد:** كل استعلامات قاعدة البيانات معزولة في ملف واحد
> (`src/data/api.ts`). تغيير Supabase إلى مزوّد آخر مستقبلاً يعني تعديل هذا الملف وحده،
> لا إعادة بناء النظام.

## التشغيل محلياً — 4 خطوات

```bash
# 1) تثبيت الحزم
npm install

# 2) إعداد متغيرات البيئة
cp .env.example .env      # ثم املأ القيمتين (انظر «إنشاء قاعدة البيانات» أدناه)

# 3) تشغيل خادم التطوير
npm run dev               # http://localhost:5173

# 4) بناء نسخة الإنتاج
npm run build && npm run preview
```

المتطلبات: **Node.js 18** فأحدث.

## إنشاء قاعدة البيانات (مجاناً)

1. سجّل حساباً على **[supabase.com](https://supabase.com)** ← **New project** ← اختر الخطة **Free**.
   احتفظ بكلمة مرور قاعدة البيانات في مكان آمن.
2. من القائمة الجانبية افتح **SQL Editor** ونفّذ الملفات **بهذا الترتيب**:

   | # | الملف | ماذا يفعل |
   |---|---|---|
   | 1 | `supabase/migrations/0001_schema.sql` | ينشئ الجداول والعلاقات والفهارس |
   | 2 | `supabase/migrations/0002_rls_and_rpc.sql` | سياسات الأمان والدوال المحكومة |
   | 3 | `supabase/migrations/0003_storage.sql` | مخازن الصور والكتب والمرفقات |
   | 4 | `supabase/migrations/0005_complaint_submit.sql` | دالة إرسال الشكوى وتقييد المعدل |
   | 5 | `supabase/seed/0001_seed.sql` | البيانات المبدئية (التخصصات والمواد والإعدادات) |

3. من **Project Settings ▸ API** انسخ:
   - `Project URL` ← ضعه في `VITE_SUPABASE_URL`
   - `anon public` key ← ضعه في `VITE_SUPABASE_ANON_KEY`

   ضعهما في ملف `.env` في جذر المشروع.

4. **أنشئ أول حساب إداري:**
   - **Authentication ▸ Users ▸ Add user** — أدخل بريداً وكلمة مرور، وفعّل *Auto Confirm User*.
   - انسخ `User UID` الظاهر بعد الإنشاء.
   - افتح **SQL Editor** ونفّذ:

     ```sql
     insert into public.admin_users (user_id, full_name, email, role)
     values ('ضع-الـ-UID-هنا', 'الاسم الكامل', 'البريد@example.com', 'super_admin');
     ```

   - ادخل الآن على `/admin/login` بهذا البريد وكلمة المرور.

> ⚠️ **مفتاح `service_role` لا يُوضع في ملفات المشروع إطلاقاً.** المفتاح الوحيد المستخدم في
> الواجهة هو `anon` العام، والحماية الحقيقية من سياسات RLS داخل قاعدة البيانات.

## النشر (Deployment)

### Cloudflare Pages — الخيار الموصى به

1. ارفع المشروع إلى مستودع على GitHub (تأكد أن `.env` غير مرفوع — `.gitignore` يمنعه).
2. من **Cloudflare Dashboard ▸ Workers & Pages ▸ Create ▸ Pages ▸ Connect to Git**.
3. الإعدادات:
   - **Framework preset:** `Vite`
   - **Build command:** `npm run build`
   - **Build output directory:** `dist`
4. **Settings ▸ Environment variables** — أضف `VITE_SUPABASE_URL` و `VITE_SUPABASE_ANON_KEY`.
5. **Deploy**. ملف `public/_redirects` مضمَّن بالفعل ليعمل التوجيه الداخلي للصفحات.

### Vercel / Netlify
نفس الخطوات: أمر البناء `npm run build`، مجلد الإخراج `dist`، ونفس متغيري البيئة.

### ربط نطاق (Domain) لاحقاً
Cloudflare Pages ▸ **Custom domains ▸ Set up a domain** ← أدخل النطاق واتبع تعليمات سجلات DNS.
شهادة SSL تُصدر تلقائياً ومجاناً.

## مصادر المحتوى المبدئي

البيانات المبدئية مستخرجة من وثائق نظام ISO 21001 المعتمدة بالمركز:

| الوثيقة | ما أُخذ منها |
|---|---|
| `ISO-GEN-SC-01` بيان نطاق النظام | أسماء التخصصات السبعة الرسمية · موقع المركز |
| `ISO-GEN-PO-01` سياسة النظام | المجال · الرسالة · القيم |
| `ISO-GEN-OB-01` أهداف النظام | أهداف الجودة ومستهدفاتها |
| `ISO-EDU-PR-01` الإجراء التشغيلي الرئيسي | إدارات المركز · المواد الدراسية لكل صف وتخصص |
| `ISO-COM-MN-01` دليل الطالب وولي الأمر | المخاطر الرئيسية ومهمات الوقاية لكل ورشة · مدد الرد على الشكاوى |

ما لم يرد في هذه الوثائق كُتب كمحتوى عام قابل للتعديل، أو تُرك كـ
`[يتم تحديث هذه البيانات من لوحة الإدارة]`. **لم تُخترع أي معلومة رسمية.**

> البيانات المبدئية ليست ثابتة: يمكن تعديلها أو حذفها بالكامل من لوحة الإدارة،
> أو حذف كل ما أضافه ملف البذور بأمر SQL واحد (انظر `docs/04-admin-guide.md`).

## الأمان

- **RLS مفعَّل على كل جدول** — القراءة العامة مقصورة على المحتوى المنشور فقط.
- **بيانات الطلاب لا تُقرأ علناً إطلاقاً** — لا سياسة قراءة عامة على `students` ولا `attendance_records`.
  الوصول الوحيد عبر دالة `parent_portal_login` المحكومة، التي تتحقق من الهوية وتقيّد المحاولات.
- **الرقم القومي** يُستخدم للتحقق فقط ولا يُعاد إرساله إلى المتصفح.
- **الشكاوى**: الزائر يستطيع الإرسال فقط؛ القراءة والتعديل للإدارة. والتتبع العام يشترط
  الرقم المرجعي **ورقم الهاتف** معاً.
- **مرفقات الشكاوى** في مخزن خاص لا يُقرأ إلا بواسطة الإدارة.
- **لوحة الإدارة** محمية على مستويين: جلسة Supabase Auth + وجود المستخدم مفعَّلاً في `admin_users`،
  وكل عملية كتابة تتحقق من ذلك في قاعدة البيانات نفسها لا في المتصفح.
- **لا أسرار في الواجهة** — `.env` مستبعَد من Git، ومفتاح `service_role` غير مستخدم إطلاقاً.

## الأداء

- تقسيم الحزم: كل صفحة ملف مستقل يُحمَّل عند زيارتها.
- `pdfjs` (≈360KB) و `xlsx` (≈425KB) لا تُحمَّلان إلا عند فتح كتاب أو استيراد ملف.
- مشغّل يوتيوب لا يُحمَّل إلا عند ضغط زر التشغيل.
- الصور بـ `loading="lazy"` و `decoding="async"`.
- فهارس على كل أعمدة التصفية والبحث في قاعدة البيانات.
- ترقيم صفحات في كل القوائم الطويلة.
- تخزين مؤقت للإعدادات والبيانات عبر TanStack Query.

**حجم أول تحميل للصفحة الرئيسية:** ≈ 110 كيلوبايت مضغوطة.

## الإتاحة (Accessibility) و RTL

- الموقع بالكامل `dir="rtl"` مع بنية جاهزة لإضافة الإنجليزية لاحقاً.
- حلقة تركيز واضحة لكل عنصر تفاعلي، وتنقل كامل بلوحة المفاتيح.
- `aria-label` على كل زر أيقوني، و `role`/`aria-live` على التنبيهات وحالات التحميل.
- أهداف لمس لا تقل عن 44×44 بكسل.
- تباين ألوان مطابق لمستوى AA.
- احترام `prefers-reduced-motion`.
